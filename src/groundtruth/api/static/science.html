1. Why not just train a classifier

The obvious approach is to train a neural network on a pile of real and edited images. It works well on images that look like its training set and collapses toward chance on generators and editing tools it has never seen. New tools ship constantly, so a detector built that way is always chasing.

Retrace instead measures properties of how cameras and codecs physically work. Those don't change when a new editor is released. The trade is that each measurement is narrow, has a knowable failure mode, and can be checked by hand — which is what this page is for.

2. Embedded preview

The only measurement here that isn't statistical.

JPEG, HEIC, TIFF and most RAW formats store a small second copy of the image inside the file. Many editors rewrite the main image and never regenerate that copy. When that happens, the preview is a photograph of the original — real pixels, not an inference.

How the comparison is made

The main image is downscaled to the preview's size rather than the preview being upscaled. Enlarging a 160×120 thumbnail to 4000px invents detail that was never recorded, and the interpolation error would swamp the real difference. Both images are compared where both actually carry information.

The preview was encoded separately, so it differs in brightness and colour even when the content is identical. A per-channel gain and offset is fitted by least squares before differencing:

g = cov(x, y) / var(x) // x = preview, y = downscaled main b = mean(y) − g · mean(x) x' = clip(g · x + b, 0, 255)

Gain and offset are global, so a genuinely altered region cannot be absorbed by the fit — only whole-frame tone shifts can.

δ(i,j) = mean over channels of |y(i,j) − x'(i,j)| / 255 τ = max(0.05, median(δ) + 6 · 1.4826 · MAD(δ)) change = clip((δ − τ) / 0.08, 0, 1)

τ has an absolute floor. A purely relative threshold reports the same fraction of any frame as changed whether or not anything was edited, because every distribution has a top few percent. 0.05 ≈ 13 intensity levels — far beyond re-encoding cost, far below a real edit.

Blind spot

Total. Any tool that regenerates the preview correctly defeats this completely, and messaging apps strip metadata wholesale. High precision, low recall.

3. Sensor noise inconsistency

An image sensor adds noise whose magnitude is set by the physics of capture. A region spliced in from another photograph carries its source's noise level; a region that was denoised or synthesised carries almost none.

Estimating the noise level

Donoho's robust estimator: the standard deviation of the finest-scale wavelet detail coefficients, measured by median absolute deviation.

HH(i,j) = ½·[ I(2i,2j) − I(2i,2j+1) − I(2i+1,2j) + I(2i+1,2j+1) ] σ̂ = MAD(HH) / 0.6745 // MAD = median(|HH − median(HH)|)

MAD, not standard deviation. A plain σ over a block containing an edge reports the edge, not the noise — every texture boundary becomes a false positive. Edges are outliers, and MAD ignores outliers.

Finding regions that disagree

Noise scales multiplicatively with sensor gain, so a splice from a higher-ISO source is a constant offset in logs rather than in absolutes. The comparison is therefore done in log space, with a robust centre and scale:

c = median( log σ̂ ) s = 1.4826 · MAD( log σ̂ ) z(b) = |log σ̂(b) − c| / s flagged = z > 3.5 reported = flagged blocks in connected components of size ≥ 2

The contiguity requirement is a physical constraint, not a tuning knob: across ~160 blocks a handful will exceed any fixed z from estimation noise alone, but a real splice is a connected region. This controls false positives without costing real detections, which raising the threshold would.

The assumption that breaks — see §8

This treats the frame as having one global noise level. That is false for real photographs, and it is the single reason Retrace does not currently work on them.

4. JPEG block grid misalignment

JPEG divides the image into 8×8 blocks anchored to the origin and quantises each independently. That leaves faint discontinuities at every block boundary — a grid, baked into the pixel values.

Paste a region from another JPEG and it brings its own grid, shifted by wherever it landed. Only 1 offset in 64 lands back in phase. This is a geometric argument rather than a statistical one: not "this region looks unusual" but "this region's compression grid is offset from its surroundings, and no camera produces that."

Measuring the grid

The naive measure — the size of the step across a candidate boundary — is useless on textured content, because texture produces large steps everywhere and lifts all eight phases together. What identifies a block boundary is that the step there exceeds the steps immediately beside it:

d(j) = |I(j+1) − I(j)| e(j) = d(j) − ½·[ d(j−1) + d(j+1) ] // excess step E(p) = mean{ e(j) : j ≡ p (mod 8) }, p = 0…7 phase = argmax E, snr = (max E − mean E_others) / max(std E_others, 0.05)

Texture inflates a boundary and its neighbours equally, so it cancels in e. The scale floor of 0.05 matters: dividing by the observed spread alone diverges whenever the other phases happen to agree, which reads as overwhelming confidence in a featureless region.

Phase is estimated per 64px window (stride 32). A window is used only if snr ≥ 3. The frame's own phase is the mode across confident windows, and a region is reported only when several windows agree with each other on the same foreign phase — not merely differ from the host.

Measured operating envelope

ConditionResult
Composite saved at q ≥ 92Detected
Composite saved at q = 88Complete miss — 0 of ~100 readable windows
Smooth or low-texture imageNo readable grid; abstains
Paste offset ≡ (0,0) mod 8Invisible by construction

Below ~q92 the re-save quantises hard enough that its own origin-anchored grid overwrites the foreign one. The evidence is physically gone from the pixels; no estimator recovers it.

5. Error Level Analysis

Re-save the image at a fixed quality and measure how much each region changes. Regions with a different compression history should change by a different amount.

ELA is included as a baseline to beat, not as a signal. It is the most famous and most over-trusted technique in this field:

  • It confounds texture with tampering — busy regions of an authentic photo light up exactly like a splice.
  • It is meaningless on images that were never JPEG, or saved near the probe quality.
  • It produces confident-looking output on random input, which is what makes it dangerous.

Retrace suppresses the part of the error that local texture explains, and then caps ELA's confidence at 0.30 by construction so it can never drive a verdict.

6. Claim context

The cheapest and most decisive check, using no machine learning at all. If a photograph's EXIF capture time precedes the policy start date, the damage predates the coverage — and pixel-perfect authenticity is irrelevant.

It is worth stating plainly that a single integer comparison outranks every measurement above it on this page. The most sophisticated system is not always the smartest one.

7. Combining the measurements

Each detector returns three separate things, and conflating them is the usual way a multi-detector system quietly produces nonsense:

FieldMeaning
applicableWhether this detector can speak to this input at all
scoreP(edited) from this detector alone. 0.5 means no information
confidenceHow much the detector trusts itself on this input

Detectors reporting applicable = false are excluded, not folded in as neutral. "I cannot measure this" and "I measured and found nothing" are different claims, and averaging them together corrupts the result.

pooled = Σ(confidence · logit(score)) / Σ(confidence) P(edited) = sigmoid(pooled)

Known problems with this, stated plainly

1. It assumes the detectors are independent. They are not — several compression measurements read the same underlying artefacts and will agree for reasons unrelated to editing.
2. The output is not calibrated. A reported 0.9 does not mean "right 90% of the time", so the decision thresholds are ordering, not probability.
3. The weights are hand-set rather than learned.

This is a baseline that exists so the pipeline runs end to end. It should be replaced by a learned fusion with explicit calibration, verified on a reliability diagram.

8. What happens on real photographs

Everything above was verified against manipulations generated in-house, with pixel-exact ground truth. Those tests pass. Then it was measured against the Korus Realistic Tampering Dataset — 112 real photographs edited by hand in GIMP and Affinity Photo, with their 112 matched unedited originals.

SyntheticReal photographs
Localisation hit rate0.990.010
Unedited images cleared100%0%
Edited images flagged100%18.8%
Unedited falsely flagged0%19.6%

The false positive rate exceeds the true positive rate, and the two score distributions are identical to three decimal places. That is chance performance.

The diagnosis

Running the noise measurement on matched pairs of the same scene:

image edited unedited r09696ba3t 189 blk 186 r1e3303ebt 192 220 ← unedited scores higher r2410fbc3t 256 260 ← unedited scores higher r36610622t 0 317 ← unedited flagged, edited clean

Mean separation is −0.065. The edited image scores higher than its own original on 4 of 14 pairs — worse than a coin flip.

The cause is §3's assumption. Photon shot noise scales with the square root of signal, so bright regions of a completely untouched photograph are genuinely noisier than dark ones. Hundreds of blocks legitimately deviate from any single global level — and they deviate identically in both versions, because the two files are the same photograph apart from a region covering ~5% of the frame.

The real lesson is about the test, not the detector

The synthetic fixture generated a scene with uniform noise and pasted in a region with a different uniform level — precisely the world the detector models. It scored 0.99 because the test could not have failed. It was measuring whether the code matched its own premise, not whether the premise was true.

Synthetic fixtures verify that a detector fires in the right place given its assumptions. Only real data tests whether those assumptions hold.

What has to change

  • Model noise as a function of local brightness — a noise level function — and flag deviation from that model rather than from a constant.
  • Add a matched-pair regression harness, so scene-level variation cancels.
  • Validate the compression measurements on a JPEG corpus. The Korus images are TIFF, so the entire compression tier correctly abstained on all 224 and remains unverified on real data.

Retrace reports what it can measure and says plainly when it cannot. A result is evidence for a human decision, not the decision itself.
